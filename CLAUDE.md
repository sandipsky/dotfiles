# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Personal Arch Linux dotfiles for a Hyprland + hypr-shell desktop (hypr-shell is a GTK4 shell developed in the separate `~/Projects/hypr-shell` repo; it replaced the previous Quickshell-based shell on 2026-09-05). There is no build step and no test suite — the "deliverable" is the contents of `~/.config`, `~/.local`, and a few system paths (udev rules, fonts, icons, `.desktop` overrides). Everything is wired together by [install.sh](install.sh) on Arch; [fedora.sh](scripts/fedora.sh) is the GNOME-keeping Fedora Workstation variant, which installs the shared apps and hardware tuning but no Hyprland/hypr-shell (see "Distro entry points" below).

## Installing / re-applying

[install.sh](install.sh) is the main entry point, and it targets a **fresh Arch install** — it never uninstalls packages or cleans up prior setups, so don't add migration logic to it. It's still destructive in places (overlays files into `~/.config/`, edits `/etc/sudoers` and `/etc/systemd/system/`, ends with `reboot`) — never run it on a machine you haven't already backed up.

It expects Arch with `pacman` and `yay`, and is run as the **normal user** — it refuses to start as root (`yay`/`makepkg` won't build as root), asks its two y/n questions first (Plymouth boot splash? SDDM login screen instead of direct tty1 login?), then asks for the sudo password once (`sudo -v`), and a background keepalive refreshes the sudo timestamp for the whole run so long builds never stall on a mid-run re-prompt (`logname` discovers the user). Typical usage:

```
./install.sh
```

[rebuild-nautilus.sh](scripts/rebuild-nautilus.sh) is the day-to-day helper for the vendored Nautilus fork (see "Nautilus (file manager fork)" below): run it **as your user** with `./scripts/rebuild-nautilus.sh` after editing the source — it builds the package from [applications/nautilus-fork/](applications/nautilus-fork/) and installs it. It's DE-safe by design: the fork replaces the official `nautilus` package in place (same name), the `pacman -U` step is deliberately interactive so any proposed conflict removals must be confirmed, and it refuses to silently downgrade if the installed nautilus is newer than the fork (prompts; the right fix is bumping the vendored tree).

What it does, in order: sets up DNS first so the rest of the install isn't throttled (the GLX router's first DHCP DNS server, 110.44.112.200, is dead and glibc stalls 5 s per lookup on it — the script pins working resolvers on the `GLX` Wi-Fi profile when present, enables systemd-resolved with the stub-resolv.conf symlink, and restarts NetworkManager), installs Hyprland/etc. packages, installs AUR packages via `yay`, extracts the vendored hypr-shell source tarball ([applications/hypr-shell/hypr-shell.tar.gz](applications/hypr-shell/), a `git archive` of the hypr-shell repo at `~/Projects/hypr-shell`, refreshed by running `./package.sh` in that repo and copying its `dist/hypr-shell.tar.gz` here) and runs its own `install.sh`, which installs the missing pacman build deps and builds into `~/.local` — never a `git clone`, so the install reproduces offline — builds and installs the Nautilus fork from [applications/nautilus-fork/](applications/nautilus-fork/) (the official `nautilus` package is never installed — `pacman -U` resolves the fork's runtime deps itself) and adds `IgnorePkg = nautilus libnautilus-extension` to `/etc/pacman.conf` — copies the udev rules from [assets/](assets/) into `/etc/udev/rules.d/` (substituting `$USERNAME`), installs `assets/bin/extract-audio` to `/usr/local/bin` (extracts video audio tracks as MP3 — DaVinci Resolve on Linux can't decode AAC; canonical copy also lives at `~/resolve/extract-audio.sh`, whose resolve-restore.sh skips installing its own if this one is on PATH), copies font assets into `/usr/share/fonts`, installs `.desktop` overrides into the user's `~/.local/share/applications/`, copies [config/](config/) into the user's `~/.config/`, substitutes `USERNAME` into `config/hypr/conf/{keybinds,autostart}.lua` and `config/hypr-shell/config.json` (absolute `/home/USERNAME/.local/bin/hypr-shell` paths), seeds the user's avatar at `~/.face` from [assets/profile.png](assets/profile.png), optionally installs Plymouth by running `./scripts/plymouth.sh install`, sets up the login path — by default tty1 autologin + a `.zprofile` that `exec uwsm start hyprland.desktop`; if the SDDM prompt was answered yes, it instead runs `./scripts/sddm.sh install` (SDDM + the Elegant theme, `sddm.service` enabled, no autologin pieces) — sets gsettings + xdg-mime defaults, runs `xdg-user-dirs-update`, then reboots.

### Root vs. user pattern

The script runs as the normal user, never as root — it exits early if `$EUID` is 0, because `yay` and `makepkg` refuse to build as root. It authenticates sudo once at the top (`sudo -v`) and a background keepalive (killed by a `trap … EXIT`) refreshes the credential cache every 60 s, so the long pacman/yay/makepkg steps never stop midway to re-prompt — this also covers the `sudo` calls that yay/makepkg make internally, since they share the same tty timestamp. The split when adding commands:

- System paths (`/etc`, `/usr/share`, `/usr/local`, `pacman -S`/`-U`, `systemctl`) — prefix with `sudo`.
- The user's home, `yay`, `makepkg`, `xdg-mime`, `xdg-user-dirs-update` — run plainly as the user. Many of these lines still carry a `sudo -u "$USERNAME"` prefix from the script's older run-as-root layout; that's now a harmless no-op (sudo to yourself), fine to keep or drop when touching a line.
- `dconf load` / `gsettings set` keep the `dbus-run-session --` wrapper — on a fresh install the script runs from a bare tty with no session bus.

The script consistently uses `/home/$USERNAME/…` rather than `~`/`$HOME` (a holdover from the run-as-root layout that also keeps paths unambiguous inside `sudo` heredocs) — keep doing that.

The Lua config auto-reloads on save; `Super+Shift+N` (bound to `hyprctl reload`) forces a reload manually. Restart hypr-shell by killing `hypr-shell` and relaunching `~/.local/bin/hypr-shell` (or run `./install.sh --restart` in the hypr-shell repo after rebuilding it).

## Distro entry points

The scripts come in two layers, and the split decides where a new change belongs:

- **Base OS + apps** — arch.sh (now maintained in its own separate repo, no longer here) runs **as root from the Arch live ISO** (partitions, `pacstrap`, locale/bootloader, Intel/NVIDIA, zram, battery threshold, zsh/starship, wine/gaming, dev stack, optional KDE). [ubuntu.sh](scripts/ubuntu.sh) is its Ubuntu counterpart and runs **with `sudo`** on an already-installed Ubuntu GNOME (purges snap, adds the Chrome/VS Code/Docker apt repos, wine/lutris and the dev stack/Postman — each prompted up front, Spotify with adblock, the workspace-switcher-overlay disabler extension, silent boot, NTFS mount, the Fira font; stock Nautilus — the fork is Arch-only). [fedora.sh](scripts/fedora.sh) is the Fedora member of this layer — run **as the normal user** on a fresh Fedora **Workstation**, keeping GNOME as the desktop: it installs the shared app/dev/hardware sections (see the fedora.sh list below) and adds two GNOME Shell extensions, Dash to Dock (Fedora's `gnome-shell-extension-dash-to-dock` package) and "Disable Workspace Switcher Overlay" (fetched from extensions.gnome.org, id 6358, for the running Shell version, then `gnome-extensions enable`d — both activate at next login). None of these installs Hyprland or hypr-shell; the base OS itself needs no script on Fedora, since Anaconda handles partitioning/bootloader.
- **Hyprland + hypr-shell desktop** — [install.sh](install.sh) on Arch, run **as the normal user**. Arch is the only distro that gets this desktop (the old fedora-hyprland.sh variant was removed — on Fedora, use fedora.sh and keep GNOME). [kde.sh](scripts/kde.sh) is the KDE Plasma alternative to install.sh on Arch (also run as the normal user): Plasma + SDDM (deliberately no autologin), stock KDE apps instead of the Hyprland setup's picks (Dolphin — not the Nautilus fork, Konsole — not alacritty, Gwenview/KCalc/Ark/Okular/Kate/Spectacle), and no hypr-shell; it leaves power-profile switching, idle/lock, rfkill and clipboard to Plasma (no udev rules/user units, no breezex-cursor-theme) and installs only the desktop-agnostic config (vim) plus the shared assets (fonts, icons, extract-audio, spotify-adblock, music app).

`config/` and `assets/` are the shared payload — the per-distro scripts differ only in how packages and the vendored builds get installed (fedora.sh copies only the desktop-agnostic configs: vim). Keep distro-specific paths out of `config/`: where a distro's layout differs, its script bridges it rather than editing the shared configs.

What fedora.sh deliberately does differently from install.sh/arch.sh — don't "fix" these back (it leaves session, lock, power-profile and rfkill handling to GNOME):

- Nautilus is the stock Fedora package — the vendored fork is Arch-only (same on Ubuntu); install.sh is the only script that builds it. `restorecon` runs over everything written under `/etc` and `/usr/local` (SELinux).
- RPM Fusion provides full `ffmpeg` (replacing Workstation's ffmpeg-free), negativo17 the native Spotify client that `spotify-adblock` preloads into, and `/etc/dnf/dnf.conf` gets `max_parallel_downloads=10` + `fastestmirror=True` when unset. Nothing touches sudoers — install.sh's last step only undoes an archinstall-only NOPASSWD line.
- Packages install with `--skip-unavailable` and the script then verifies the *commands* the rest of the run depends on, aborting with the list, so a package renamed between Fedora releases fails loudly instead of silently degrading. Optional pieces (music app, Spotify, the e.g.o extension) are best-effort and reported in a summary at the end rather than aborting the run. The dev and gaming stacks are prompted up front (both scripts); there is deliberately no cursor-theme install — GNOME keeps Adwaita.
- NVIDIA comes from RPM Fusion's `akmod-nvidia` (arch.sh uses `nvidia-open-dkms`), and the whole NVIDIA step is skipped inside any VM (`systemd-detect-virt`); VirtualBox guests get the guest additions instead — ubuntu.sh does the same VM detection. Kernel args go through grubby/BLS entries rather than a systemd-boot loader entry, and the dGPU is offload-only — the TUF F15's panel is wired to the Intel iGPU — so none of arch.sh's early-KMS initramfs work for nvidia carries over. The runtime-PM modprobe options and `80-nvidia-pm.rules` udev rules are copied from arch.sh verbatim. If Secure Boot is enabled (likely, with the Windows dual boot), the script generates an akmods signing key and `mokutil` interactively asks for a one-time password to enroll it on the next boot — that prompt is expected, not a hang.
- Boot: GRUB hidden with `GRUB_TIMEOUT=0` + os-prober off (Windows boots via the firmware boot menu, Esc on ASUS), quiet/fast kernel args added via a dedup-checking grubby helper, and `NetworkManager-wait-online` masked. Workstation already ships Plymouth's `bgrt` splash, so there is no splash or dracut work.

Day-to-day helpers: [rebuild-nautilus.sh](scripts/rebuild-nautilus.sh) is Arch-only (`makepkg` + `pacman -U`) — and Arch is the only distro running the fork, so there is no Fedora/Ubuntu rebuild helper. [fix-dns.sh](scripts/fix-dns.sh) is the standalone form of the DNS fix that install.sh and fedora.sh start with. [plymouth.sh](scripts/plymouth.sh) `install|remove|status` adds or removes the Plymouth boot splash on a system set up by arch.sh + install.sh (install.sh calls its `install` when the prompt is answered yes): it inserts the `plymouth` mkinitcpio hook right after `systemd`, appends `splash` to every `/boot/loader/entries/*.conf`, clones the default theme to `<theme>-nologo` — same theme minus `watermark.png`, the Arch logo under the spinner, cloned rather than deleted in place so a plymouth upgrade can't bring the logo back (bgrt has no images of its own, so the clone is built from the theme's `ImageDir`), and gives the clone a bigger, lower spinner — the `throbber-*.png` frames are redrawn as SVG (geometry measured from upstream's 32 px frames) and rendered with `rsvg-convert` at `SPINNER_SIZE` (48 px; upscaling the rasters looked blurry) and `VerticalAlignment` set to `SPINNER_VALIGN` (.76, upstream .7), both tunables at the top of the script since the two-step plugin has no spinner-scale key — sets it default with `plymouth-set-default-theme -R` (rebuilds the initramfs), and masks the plymouth-poweroff/reboot/halt/kexec units so the splash is boot-only, never on shutdown. `remove` reverses all of that (hook and `splash` out, units unmasked, clone deleted, `pacman -Rns plymouth`, `mkinitcpio -P`). Every step is idempotent. [sddm.sh](scripts/sddm.sh) `install|uninstall|status` (`install` is the default) switches the login path on a system set up by install.sh, in either direction, and is also what install.sh calls when its SDDM prompt is answered yes: `install` does `pacman -S sddm` + `qt6-5compat`, copies the Elegant theme to `/usr/share/sddm/themes/`, selects it via `/etc/sddm.conf.d/10-theme.conf` together with the desktop's cursor (`CursorTheme=BreezeX-Light`, `CursorSize=24` plus the same `XCURSOR_*` in `GreeterEnvironment` — the values from environment.lua/gtk settings; `breezex-cursor-theme` gets installed via yay if missing, `xorg-xsetroot` via pacman because sddm applies the cursor to the X root window with `xsetroot` and silently keeps X's stock cursor without it, and `xorg-xrdb` for `/usr/local/bin/sddm-xsetup`, set as `[X11] DisplayCommand` — it loads `Xcursor.theme`/`Xcursor.size` X resources before the greeter starts, which is the only cursor-theme source Qt6's xcb backend (libxcb-cursor) honours; `XCURSOR_THEME` alone leaves the greeter on the `default` theme, i.e. Adwaita), installs `assets/profile.png` as `/usr/share/sddm/faces/<user>.face.icon` (the greeter can't read `~/.face.icon` in a 0700 home), preseeds `/var/lib/sddm/state.conf` with the user and the `hyprland-uwsm.desktop` session, removes the getty@tty1 autologin override and the `uwsm start` block from the login profile, and enables `sddm.service`; `uninstall` reverses that and writes the override and profile block back (the same heredocs as install.sh — keep them in sync). It never starts or stops sddm live; changes apply at the next boot. The vendored theme is a rewrite of Elegant in the style of hypr-shell's lock screen (`data/css/lock.css` in the hypr-shell repo) — don't re-copy an upstream version over it: GDM's solid `#222226` background (gnome-shell's `$_gdm_bg`), a borderless 130 px round avatar, the account's full name (`realName`, GECOS, falling back to the login name — the login itself always uses the login name) in Fira Sans SemiBold, a 200×30 password pill with an accent caret and an eye toggle (Enter submits, no button), an error pill for failed logins, and round icon buttons bottom-right that open lock-screen-style menus (sessions, users when there are several, power). Colours are derived from the accent with the same maths as hypr-shell's `palette.hpp`; `theme.conf` holds the defaults and `theme.conf.user` (same dir, root-owned) the machine's values: `sddm.sh` writes only its `accent` key (replace-or-append, from the live `ui.accent`), while hypr-shell-settings' "Login screen" page (`src/settings/login_page.cpp` in the hypr-shell repo; its sidebar row only appears when sddm, the theme and `Current=Elegant` are all present) writes the rest through `pkexec` on Apply — `background` (solid colour, GDM's `#222226` default with a reset), `backgroundMode` (`color`/`image`), `backgroundImage` (its copy of the chosen file as `background.<ext>` in the theme dir, since the sddm user can't read a 0700 home) + `backgroundSource`, `backgroundBlur` (0–1 like `lock_screen.blur`), `showSessionMenu`, `defaultSession` (a sessions `.desktop` path that beats SDDM's remembered one). `sddm.sh install` preserves `theme.conf.user` and `background.*` across its re-copy of the theme; Main.qml's header documents the keys. Icons are glyphs from the Tabler icon font bundled in `Elegant/fonts/` (copied from hypr-shell's `data/fonts/`, MIT) because the greeter can't read `~/.local/share/fonts`. Qt6 only (`Qt5Compat.GraphicalEffects` from `qt6-5compat` for the avatar mask; `metadata.desktop` declares `QtVersion=6`). Test-render without logging out: `sddm-greeter-qt6 --test-mode --theme assets/sddm-themes/Elegant`.

## Top-level layout

- [applications/](applications/) — vendored applications built/installed from the repo. `hypr-shell/` — source tarball of the hypr-shell repo (install.sh extracts it and runs its install.sh; see "hypr-shell (the UI layer)" below). `nautilus-fork/` — a PKGBUILD plus the full vendored Nautilus source tree (see "Nautilus (file manager fork)" below). `music/` — a meson-built music app whose own install.sh installs it to `~/.local`.
- [assets/](assets/) — files that get copied to **system** locations during install (udev rules, fonts, app icons, `.desktop` overrides, a `nautilus` dconf dump), plus `profile.png`, which becomes the user's `~/.face` avatar (and the SDDM avatar when SDDM is chosen). `sddm-themes/` holds the Elegant SDDM theme (Qt6-ported), installed by [sddm.sh](scripts/sddm.sh), the optional SDDM login-path switcher (see "Day-to-day helpers").
- [config/](config/) — copied verbatim to `~/.config/` (`alacritty`, `gtk-3.0`, `hypr`, `hypr-shell`, `systemd/user`, `vim`).
- [scripts/](scripts/) — every shell script except install.sh: the per-distro/per-desktop setup scripts (`fedora.sh`, `ubuntu.sh`, `kde.sh`) and the day-to-day helpers (`rebuild-nautilus.sh`, `fix-dns.sh`, `plymouth.sh`, `sddm.sh`). Each resolves the repo root as its parent directory (`dirname "$0"/..`), so keep that when adding scripts here. install.sh stays at the repo root and uses root-relative paths (run it from there); arch.sh, the Arch live-ISO base installer, moved to its own separate repo.
- [docs/](docs/) — loose notes (e.g. [secureboot.txt](docs/secureboot.txt) for `sbctl` enrollment). [nautilus-patches.md](docs/nautilus-patches.md) documents every local patch carried on the vendored Nautilus fork, feature by feature — keep it updated when patching the fork, so the customizations can be re-applied on a future upstream bump.

## Hyprland config

The config uses Hyprland's **Lua format** (the hyprlang `.conf` format was deprecated in Hyprland 0.55 and is removed in 0.57 — never reintroduce `.conf` files). [config/hypr/hyprland.lua](config/hypr/hyprland.lua) is intentionally tiny — it just sets the monitor and `require()`s every file in [config/hypr/conf/](config/hypr/conf/) (`animations`, `autostart`, `environment`, `keybinds`, `layout`, `windowrules`). To change behavior, edit the file in `conf/`, not the top-level `hyprland.lua`.

[autostart.lua](config/hypr/conf/autostart.lua) (via the `hyprland.start` event) launches only the polkit agent and `/home/USERNAME/.local/bin/hypr-shell` — there are deliberately no idle/night-light/wallpaper/clipboard daemons there, because hypr-shell owns all of those (see below).

Media/brightness keys, screenshot bindings (`grim`/`slurp`/`wl-copy`), and all hypr-shell panel/action bindings live in [keybinds.lua](config/hypr/conf/keybinds.lua).

## hypr-shell (the UI layer)

The shell is **hypr-shell**, a GTK4/gtkmm layer-shell desktop shell developed in its own repo at `~/Projects/hypr-shell` (not in this repo). This repo carries only a source snapshot, [applications/hypr-shell/hypr-shell.tar.gz](applications/hypr-shell/) (a `git archive`), and the config, [config/hypr-shell/config.json](config/hypr-shell/config.json). install.sh extracts the tarball and runs hypr-shell's own `install.sh`, which installs the missing pacman build deps (gtkmm-4.0, gtk4-layer-shell, libadwaita, ...) and builds into `~/.local` (`hypr-shell`, `hypr-shell-settings`, icon fonts, desktop entry). Its runtime tools (`cliphist`, `wl-clipboard`, `wtype`, `hyprsunset`, `brightnessctl`) are in install.sh's pacman list. It provides the bar (top), app menu, launcher, clipboard history, control center, notification daemon, session menu, PAM lock screen, idle management (ext-idle-notify), night light (via `hyprsunset`), wallpaper management/slideshow, and volume/brightness OSDs — which is why this repo has no hyprlock/hypridle/wpaperd/dunst configs.

Points that matter when changing things:

- **Source lives elsewhere.** Edit UI/behavior in `~/Projects/hypr-shell`, rebuild with its `./install.sh --restart`, then refresh this repo's snapshot: run `./package.sh` there and copy `dist/hypr-shell.tar.gz` to [applications/hypr-shell/](applications/hypr-shell/). Never replace the tarball with a `git clone` in install.sh — the install must reproduce offline.
- **Config.** [config/hypr-shell/config.json](config/hypr-shell/config.json) is a snapshot of the machine's `~/.config/hypr-shell/config.json` (hypr-shell hot-reloads it and merges it over built-in defaults). It contains `/home/USERNAME/...` paths (lock-screen background, current wallpaper) with a literal `USERNAME` token that install.sh `sed`s at install time — keep the token in the repo copy. The Settings app (`hypr-shell-settings`, `Super+Shift+W` opens its wallpaper page) rewrites the live file at runtime; those changes don't flow back into the repo (re-running install.sh overwrites them), so refresh the snapshot with `sed 's|/home/<user>|/home/USERNAME|g' ~/.config/hypr-shell/config.json > config/hypr-shell/config.json` when the current setup should become the installed default.
- **Actions.** Keybinds call the running instance through its GApplication command-line flags via the `shell()` helper in keybinds.lua: `--launcher` (Alt+Space / Super tap), `--clipboard` (Super+V), `--control-center` (Super+A), `--session` (Super+X), `--lock` (Super+L / XF86ScreenSaver), `--lock-and-suspend` (lid close), `--wallpaper-next` (Super+P). Volume/brightness keys call `wpctl`/`brightnessctl` directly; hypr-shell's OSD reacts to the resulting PipeWire/backlight change.
- **Idle/lock.** Idle stages (screen off, lock, suspend, each with a fade grace period) are configured under `idle` in config.json; the repo snapshot sets only `screen_off_timeout` (600 s) and `lock_timeout` (603 s); everything else uses hypr-shell's defaults (suspend at 1800 s, lock-before-suspend on, 5 s fade). Idle detection uses ext-idle-notify v1, so compositor idle inhibitors (e.g. a fullscreen video player's) are honored. There is no gamepad exemption anymore — the old joystick-wake daemon depended on the previous shell's IPC and was removed with it.
- **Clipboard.** hypr-shell spawns its own `wl-paste` → `cliphist` watchers (text and images) when `clipboard.enabled` is true — do not add a cliphist watcher back to autostart.lua.
- **Theming.** Accent color, dark mode and font come from the `ui` block in config.json; wallpapers are read from `~/Pictures/Wallpapers` (slideshow enabled).

## Nautilus (file manager fork)

The file manager on the Arch box is a local fork of GNOME Nautilus — **Arch-only**: ubuntu.sh and fedora.sh install the stock distro package instead. The full upstream source (50.2.2, matching the Arch package it replaces) is vendored at [applications/nautilus-fork/nautilus/](applications/nautilus-fork/), with local feature patches carried directly on that tree as git diffs. [applications/nautilus-fork/PKGBUILD](applications/nautilus-fork/PKGBUILD) (adapted from Arch's official one; docs subpackage and test suite dropped) builds `nautilus` + `libnautilus-extension` **only** from the vendored tree — fully offline, nothing fetched from repos/AUR/git.

Points that matter when changing things:

- **Workflow.** Edit the C/blueprint source in `applications/nautilus-fork/nautilus/`, then run [rebuild-nautilus.sh](scripts/rebuild-nautilus.sh) as your user — it copies the recipe to a temp dir, `makepkg -s`, installs both packages with `pacman -U`, and quits the running Nautilus instance so the next launch picks up the new binary. There is no hot reload — every change is a full compile (a few minutes).
- **Versioning.** The fork is `50.2.2-1.1` — a pkgrel bump over the repo's `-1` so `pacman -U` supersedes it. Both install.sh and rebuild-nautilus.sh ensure `IgnorePkg = nautilus libnautilus-extension` in `/etc/pacman.conf` so `-Syu` never replaces the fork; upgrades happen only by bumping the vendored tree. The official `nautilus` is deliberately absent from install.sh's pacman list — the fork's PKGBUILD declares all runtime deps and `pacman -U` resolves them from the repos. To return to stock: remove the IgnorePkg line, `sudo pacman -S nautilus libnautilus-extension`.
- **Patch log.** Document every feature patch in [docs/nautilus-patches.md](docs/nautilus-patches.md) (by behavior, not diff) so it can be re-applied when bumping upstream. That file also records the upstream baseline commit and the bump procedure.
- **No third-party menu extensions.** "Open in Terminal" (alacritty/kitty) and "Open in Code" are patched directly into the fork's context menus (see [docs/nautilus-patches.md](docs/nautilus-patches.md)) — do not re-add `nautilus-open-any-terminal` (AUR) or code-nautilus to install.sh; they would duplicate the built-in items. rebuild-nautilus.sh removes both if it finds them installed.

## Power profiles

Automatic switching on AC plug/unplug is driven by udev (`assets/99-power.rules`) firing the `acpoweron.service` / `acpoweroff.service` systemd user units in [config/systemd/user/](config/systemd/user/), which call `powerprofilesctl set performance` / `set power-saver` directly (`power-profiles-daemon` is in the package list; hypr-shell's battery widget reads/sets the same profiles). The `usb-insert.service` / `usb-remove.service` units play a sound via `paplay` when triggered.

Note that the udev rules contain a literal `USERNAME` token that [install.sh](install.sh) `sed`s into the real user during install — same pattern as `config/hypr-shell/config.json`; when editing these files in the repo, leave the token as `USERNAME`.
